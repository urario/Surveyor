# GUIテスタビリティ解析ツール 要件定義書

作成日: 2026-07-01

本書は [gui-testability-analyzer-requirements.md](gui-testability-analyzer-requirements.md) を上流要求仕様として、Surveyor の初期版で満たすべき要件を定義する。上流要求仕様の `RQ-xxx` は変更せず、本書では派生要件を `RD-xxx` として管理する。

## 1. 目的と位置づけ

Surveyor は、長期保守されている C++/MFC/Win32 系 Windows デスクトップアプリケーションを対象に、GUI テスト自動化の前段で既存画面のテスタビリティを評価・可視化するツールである。

初期版は、GUI テストを生成・実行するツールではなく、次の判断に使う分析基盤とする。

* 自動化しやすい画面、改善後に自動化すべき画面、GUI テスト対象から外すべき画面を区別する。
* 安定識別子、操作可能性、結果判定可能性、状態制御性、独自 UI、座標・画像依存のリスクを説明する。
* 問題箇所をスナップショット画像と結び付け、開発者・QA・リーダーが同じ材料で議論できるようにする。
* 将来の比較、劣化検知、近代化計画で再利用できる構造化結果を残す。

## 2. トレーサビリティ方針

| ID | 意味 | 管理場所 |
| -- | -- | -- |
| `RQ-xxx` | 上流要求仕様の要求ID | [gui-testability-analyzer-requirements.md](gui-testability-analyzer-requirements.md) |
| `RD-xxx` | 本書で定義する派生要件ID | 本書 |
| `DES-xxxx` | 後続の基本設計・詳細設計 | `knowledge/design/` |
| `UT-xxxx` / `IT-xxxx` | 後続の単体・結合検証証跡 | `knowledge/traces/` |

要件定義上の規則は以下とする。

* 1つの `RQ-xxx` から複数の `RD-xxx` を派生してよい。
* すべての `RD-xxx` は、少なくとも1つの上流 `RQ-xxx` を持つ。
* 後続の設計・実装・テストでは、該当する `RQ-xxx` と `RD-xxx` の両方を参照する。
* 本書は要件定義であり、UIA クライアント方式、キャプチャ方式、パッケージ形態などの設計判断は固定しない。ただし、設計フェーズで決めるべき判断点として明示する。

## 6. 品質レビュー

レビュー対象は本要件定義書であり、フェーズは要求定義である。レビュー観点は `knowledge/process/quality-review-policy.md` の要求フェーズ品質ゲート、および Surveyor の必須ガードレール `RQ-048`, `RQ-051`, `RQ-052`, `RQ-054` とする。

### 6.1 指摘事項

レビュー主体はプロジェクトマネジメント視点および品質担当者視点。Severity は Major（当該スライス内で是正すべき欠陥）/ Medium（実害があり是正推奨）/ Minor（改善提案）とする。

### 6.4 Verdict

`Needs changes`

本書は上流 `RQ-xxx` から派生 `RD-xxx` への網羅（全 `RQ` に少なくとも1つの `RD`）、MVP 対象外、非侵襲性、決定性、機密データ、WinUI 3 / C# 層分離といった品質制約の骨格を満たしている。一方で、`F-01`（Section 3 と Section 4 のトレース不整合）は本書が主眼とする双方向トレーサビリティの破綻であり、当該スライス内で是正すべき欠陥である。あわせて `F-02` の自己レビューの独立性・網羅性の欠如を是正する必要がある。`F-03`〜`F-05` は安全性・機密・検証可能性のガードレールに関わる Medium であり、要求段階で受入条件を強化することが望ましい。`F-01`・`F-02` を修正し、トレース照合を再実行して整合を確認した後に `Accept with risks` へ再判定できる見込みである。
